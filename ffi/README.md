# rich-ffi — C/C++ bindings for rich-rs

A thin C ABI over [rich-rs](..), built for C/C++ consumers (e.g. the
**SafeTunnel** CLI and its `--foreground` daemon). It mirrors how SafeTunnel
already vendors the Slint C++ SDK: build once, ship prebuilt artifacts, link
with **no Rust toolchain** on the consumer side.

## What you get

| Artifact | File | Use |
|----------|------|-----|
| Static library | `librich_ffi.a` / `rich_ffi.lib` | Link straight into the C++ binary (preferred — nothing extra to ship/sign) |
| Shared library | `librich_ffi.so` / `.dylib` / `rich_ffi.dll` | Offered for flexibility |
| C header | `include/rich.h` | Generated by cbindgen; C and C++ compatible |
| C++ wrapper | `include/rich.hpp` | Header-only RAII (`rich::Console`) over the C ABI |

## Build (requires the Rust toolchain — only here, never in SafeTunnel)

```bash
cargo build --release          # from ffi/
# -> target/release/librich_ffi.a  +  include/rich.h (regenerated)
```

> **cbindgen 0.28+ is required** — it understands edition-2024's
> `#[unsafe(no_mangle)]`. Older versions silently emit an empty header.

## The ABI in one breath

```c
#include "rich.h"
RichConsole *con = rich_console_new();
rich_console_set_force_terminal(con, isatty(fileno(stdout)));  // plain when piped
char *out = rich_console_render_markup(con, "[bold green]✓[/] tunnel wg0 up");
if (out) { fputs(out, stdout); rich_string_free(out); }
rich_console_free(con);
```

C++ with the RAII wrapper:

```cpp
#include "rich.hpp"
rich::Console con;
con.set_force_terminal(::isatty(STDOUT_FILENO));
std::fputs(con.render_markup("[bold green]✓[/] tunnel wg0 up").c_str(), stdout);
```

### The daemon contract (verified)

`set_force_terminal(false)` produces **genuinely plain text** — no ANSI, no
hyperlink escapes — so the default daemon path can write to journald/syslog
safely. `set_force_terminal(true)` (or an `isatty()` that returns true under
`--foreground`) emits full styling. See `examples/smoke.cpp`.

## Ownership rules (the only way to leak/crash)

* Each `rich_console_new()` → exactly one `rich_console_free()`.
* Each non-NULL `char*` from `rich_console_render_markup()` → exactly one `rich_string_free()`.
* Inputs must be valid NUL-terminated UTF-8.

Every entry point is NULL-checked and panic-guarded: a rich-rs panic becomes a
NULL/no-op return instead of unwinding into your C++ (which would abort the
process). The crate deliberately keeps `panic = unwind` + `catch_unwind` rather
than `panic = abort`, so a styling hiccup never takes down `safetunneld`.

## Smoke test

```bash
cargo build
g++ -std=c++17 -Iinclude examples/smoke.cpp \
    target/debug/librich_ffi.a -lpthread -ldl -lm -o /tmp/rich_smoke
/tmp/rich_smoke            # piped  -> plain text
script -qec /tmp/rich_smoke /dev/null   # PTY -> ANSI
```

## Release artifacts

Pushing a `v*` tag runs `.github/workflows/release.yml`, which builds the FFI
libraries on a **native runner per platform/arch** and attaches one tarball per
target to the GitHub Release, plus a `SHA256SUMS` file. Asset naming:

```
rich-ffi-<version>-<target>.tar.gz
```

| target triple | runner | contents |
|---------------|--------|----------|
| `x86_64-unknown-linux-gnu`  | ubuntu-22.04     | `librich_ffi.a`, `librich_ffi.so` |
| `aarch64-unknown-linux-gnu` | ubuntu-22.04-arm | `librich_ffi.a`, `librich_ffi.so` |
| `x86_64-apple-darwin`       | macos-13         | `librich_ffi.a`, `librich_ffi.dylib` |
| `aarch64-apple-darwin`      | macos-14         | `librich_ffi.a`, `librich_ffi.dylib` |
| `x86_64-pc-windows-msvc`    | windows-2022     | `rich_ffi.lib`, `rich_ffi.dll`, `rich_ffi.dll.lib` |
| `aarch64-pc-windows-msvc`   | windows-11-arm   | `rich_ffi.lib`, `rich_ffi.dll`, `rich_ffi.dll.lib` |

Each tarball unpacks to `rich-ffi-<version>-<target>/{include/{rich.h,rich.hpp},lib/...}`
— drop `include/` + `lib/` straight into `third_party/rich/<arch>/`.

## Consuming from SafeTunnel (the Slint pattern)

1. CI in rich-rs builds the libraries per platform/arch (see above) and attaches
   them to the GitHub Release.
2. SafeTunnel adds `third_party/rich/fetch_rich.sh` + `MANIFEST.md` (copied from
   the Slint fetch script) that downloads + checksums the matching
   `rich-ffi-<version>-<target>.tar.gz` into `third_party/rich/<arch>/{include,lib}`.
3. CMake links them:

   ```cmake
   # -DCMAKE_PREFIX_PATH=third_party/rich/amd64
   find_library(RICH_LIB rich_ffi REQUIRED)
   target_link_libraries(safetunnel_cli PRIVATE ${RICH_LIB} pthread dl m)
   target_include_directories(safetunnel_cli PRIVATE third_party/rich/${ARCH}/include)
   ```

   On Windows, link `rich_ffi.lib` plus `ntdll userenv ws2_32 bcrypt` (the
   crossterm/std dependencies); `cargo rustc --crate-type staticlib -- --print
   native-static-libs` prints the exact list per target.
